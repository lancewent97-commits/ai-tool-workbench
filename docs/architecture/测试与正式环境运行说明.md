# 测试与正式环境运行说明

## 1. 环境边界

平台只维护两套运行环境：

- 测试平台：用于页面、接口、AI 推荐、工具上传、发布、下载、回传和审核的完整验证，可以保留演示数据。
- 正式平台：用于公司内部真实使用，初始只包含数据库结构，不包含工具、版本、用户行为或演示数据。

两套环境必须隔离数据库、文件目录、会话 Cookie 和运行端口。测试环境的数据库备份或文件目录不得直接覆盖正式环境。

## 2. 本地端口与资源

| 项目 | 测试平台 | 正式平台本地预览 |
| --- | --- | --- |
| Web | 3000 | 3001 |
| API | 3100 | 3200 |
| PostgreSQL 数据库 | `ai_tool_workbench` | `ai_tool_workbench_production` |
| 文件根目录 | `var/test` | `var/production` |
| 会话 Cookie | `atw_test_session` | `atw_production_session` |
| 页面标识 | 测试环境 | 正式环境 |

本地可以共用一个 PostgreSQL 服务，但必须使用两个独立数据库。正式内网部署时应进一步使用独立数据库实例或独立受控数据库服务。

## 3. 测试平台启动

```bash
pnpm db:up
pnpm dev:api:test
pnpm dev:test
```

访问：

- 用户工作台：`http://127.0.0.1:3000`
- 维护工作台：`http://127.0.0.1:3000/admin`
- API 健康检查：`http://127.0.0.1:3100/health`

需要重新填充演示工具时执行：

```bash
pnpm db:seed
```

演示数据脚本同时检查`PLATFORM_ENV=test`和`ALLOW_DEMO_SEED=true`。即使误传正式数据库地址，只要数据库名包含 production 或 formal，也会拒绝执行。

## 4. 正式平台初始化与本地预览

从`.env.production.example`复制并生成本机私有的`.env.production.local`。正式服务器必须替换数据库密码、Cookie 安全配置和模型配置。

创建空数据库并执行迁移：

```bash
pnpm db:init:production
```

启动本地正式环境预览：

```bash
pnpm dev:api:production
pnpm dev:production
```

访问：

- 用户工作台：`http://127.0.0.1:3001`
- 维护工作台：`http://127.0.0.1:3001/admin`
- API 健康检查：`http://127.0.0.1:3200/health`

本地正式预览允许使用 HTTP，所以`.env.production.local`暂时使用`NODE_ENV=development`和`COOKIE_SECURE=false`。真正部署时必须改为：

```text
NODE_ENV=production
COOKIE_SECURE=true
```

正式平台禁止使用`AI_PROVIDER=external-dev`。

## 5. 正式平台首次启用

完成数据库、文件存储、内网地址和 HTTPS 配置后，再创建首位正式管理员：

```bash
pnpm bootstrap:admin:production
```

管理员登录后，通过正式上传流程逐个录入真实工具。测试工具、测试下载记录、测试回传和测试 AI 对话不迁移。

## 6. 验证路径

当前产品闭环只在测试平台验证：

1. 上传主工具、版本或衍生工具。
2. 自动检查并发布。
3. AI 对话推荐工具并生成工具包。
4. 下载后交给本地 Agent。
5. 回传调整后的工具包。
6. 自动检查、人工审核并发布。
7. 检查工具谱系、历史版本、默认下载、下架和更新提醒。

整条路径稳定后，在正式平台重新上传经过确认的真实工具，不复制测试数据。
